# Bella Virtual — Operating Model

_How the company is organized and how the work flows. One page, kept current. Each department owns its own SOPs; this map shows who owns what and where the handoffs are._

- **Owner:** Ops lead · **Version:** 0.1 (draft) · **Last reviewed:** set on adoption · **Review cadence:** quarterly

## Operating principle
Everything below exists to keep one promise: **one designer-made standard on every property, MLS-ready in 24–48 hours, with unlimited revisions for two weeks.** Real interior designers, never one-click AI. If a decision doesn't protect *quality, speed, or that standard*, it's the wrong decision.

## The end-to-end flow (where the handoffs are)
```
Lead ──▶ Order placed ──▶ Intake/validate ──▶ Assign ──▶ Stage ──▶ Internal QA ──▶ Deliver ──▶ (Revisions ⟳) ──▶ Approved/Sold
 │            │                                                                              │
Marketing  Sales/Partnerships                     Production / Quality / Fulfillment      Support / Success
                                                                                             │
                                                                              Finance (invoice · partner payout)
```

## Operating cadence
- **Daily** — Production/Fulfillment stand-up: at-risk orders, capacity for the day.
- **Weekly** — Ops review: SLA %, queue health, revision/rework trends; Sales pipeline.
- **Monthly** — Business review: revenue, margin, partner payouts, CSAT; SOP updates.
- **Quarterly** — Review every SOP + this map; retire what's stale.

## Ownership rules
- Every SOP has **one owner**, a **version**, and a **last-reviewed date**.
- Cross-department work names a **single accountable owner** (avoid "everyone owns it → no one does").
- Prefer **checklists over prose**. Update the SOP the next time you run the process, not in a vacuum.
